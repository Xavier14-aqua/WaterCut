# WaterCut 模块与功能定位

本表面向学习、排错和扩展。路径以项目根目录为起点；每个功能先看公开入口，再进入具体实现。

## 运行目录

| 目录                    | 职责                                             | 主要入口与约束                                              |
| ----------------------- | ------------------------------------------------ | ----------------------------------------------------------- |
| `src/main`              | Electron 启动、窗口、受控接口、系统能力          | `main.ts` 组装，`ipc` 按业务注册；不执行项目 SQL            |
| `src/preload`           | 提供固定的界面能力                               | `preload.ts` 实现 `WaterCutAPI`，不暴露通用文件或数据库接口 |
| `src/workers`           | 数据任务串行队列、离线媒体探测                   | `data-worker.ts` 和 `probe-worker.ts` 是独立入口            |
| `src/renderer/app`      | 导航、工作台组装、共享状态与保存协调             | `App.tsx` → `useAppController.ts` / `AppShell.tsx`          |
| `src/renderer/features` | 用户功能的组件与交互                             | 每个功能有公开 `index.ts`                                   |
| `src/renderer/platform` | 界面使用的媒体地址、拖拽协议                     | 不包含 Node 文件访问                                        |
| `src/modules`           | 后台业务、数据读写和事务                         | 通过数据线程调用；跨模块走公开入口                          |
| `src/infrastructure`    | 文件流、哈希、空间检查、ZIP 与取消工具           | 不依赖 React 或 Electron 窗口                               |
| `src/contracts`         | 界面 API、数据线程参数 / 返回值 / 进度           | 数据线程命令有固定白名单                                    |
| `src/shared`            | 通用数据类型、校验、颜色、顺序、时长和时间线计算 | 不依赖 DOM、Node、Electron 或 React                         |
| `tests/integration`     | 项目、总库、历史格式和交付集成验证               | 使用独立临时数据                                            |
| `tests/contracts`       | 编译时接口反例                                   | 错误模块、缺少参数和数据库越权必须编译失败                  |

## 数据模块内部

`modules/project/database.ts` 打开连接和执行历史升级；`migrations/schema.ts` 保存原有版本定义。`transaction.ts` 负责一次编辑的提交 / 回滚；`repositories` 提供共享读取、素材行和顺序操作；`services` 按编辑对象组织业务。业务事务可以直接包含相关 SQL，避免为了分层把一次操作拆成多次独立提交。

`modules/library` 分为连接 / 升级、行解析、查询和各类编辑服务。基础素材查询独立于总库快照与精华片段服务，防止查询和编辑互相形成循环。

`modules/workspace` 管理项目与总库的引用、提升、资料补齐和使用索引对账；官方样例单独放在 `example.ts`。`modules/delivery/package` 分开导出、导入、独立文档重建、数据库边界验证与 manifest。

## 文档和开发脚本

产品与路线图在 `docs/product`；构建与学习操作在 `docs/development`；版本记录在 `docs/releases`；原生及专项记录在 `docs/acceptance`。

脚本按 `scripts/build`、`scripts/smoke`、`scripts/checks`、`scripts/audit`、`scripts/fixtures` 组织。程序包只带运行文件；测试、文档、源码及个人数据不进入最终包。
