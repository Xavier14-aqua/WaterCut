# WaterCut 项目学习路线

按用户操作学习，每次只追踪一条完整链路。练习使用官方示例或临时项目，保留已有素材和正式项目。

## 第一步 从入口认识四个运行环境

看 `forge.config.mts` 中四个后台入口，再读 `src/renderer/main.tsx`。主进程管理窗口和本地系统能力；preload 提供固定桥接；数据和探测分别在工作线程；React 与 Web Audio 在渲染环境。

接着阅读 `renderer/app/App.tsx`：它只连接控制器与布局。`AppShell.tsx` 组装导航和页面，`views` 组合具体功能。状态迁移与跨功能操作由 `useAppController.ts` 协调，局部交互留在功能组件内。

右侧详情先看 `app/Inspector.tsx` 的选择分派，再读 `features/inspiration/IdeaInspector.tsx`、`features/library/AssetInspector.tsx` 或 `features/storyboard/ShotInspector.tsx`。选择变化与异步资源读取由 `app/inspector/useInspectorResources.ts` 协调，字段编辑留在所属功能。

练习：找到“脚本”按钮如何切换视图，并指出切换前在哪里等待保存。

## 第二步 追踪一次脚本排序

从 `features/script/ScriptView.tsx` 的拖拽或上下移事件开始，沿以下路径阅读：

```text
ScriptView
  → 应用的 onReorder / run
  → contracts/api.ts 的 reorderScriptBlocks
  → preload/preload.ts
  → main/ipc/project.ts 的 script:reorder
  → DataClient 与 contracts/worker.ts
  → workers/data-worker.ts
  → modules/project/services/script.ts
  → transaction.ts + repositories/order.ts
```

重点：脚本行和分镜顺序共享一个连接、一个事务。不能将两个更新分别保存，否则失败时会出现两种顺序。对照 `tests/integration/library-script-storyboard.test.ts` 阅读排序和重开的验证。

## 第三步 理解自动保存

阅读 `app/editing/project-editors.ts`，观察先更新界面、再捕获项目目录与字段值。接着看 `app/save/SaveCoordinator.ts` 的合并、串行队列、失败保留和 `flush()`。

保存任务带项目 ID；旧请求不能把工作台切回另一个项目。服务端结果回填时，仍要保留本地尚未保存的编辑。查看 `SaveCoordinator.test.ts` 中连续编辑、失败重试、保存屏障和迟到结果的测试。

练习：解释“保存后立刻关闭”与“保存中又输入一段文字”各自依赖哪些保护。

## 第四步 理解项目与总库

先比较 `shared/models.ts` 中项目引用和全局素材的字段，再看 `modules/workspace/assets.ts` 的原件解析、`project-library.ts` 的引用操作，以及 `catalog.ts` 的对账。

总库保留原件，项目保留自己的引用、裁剪和卡片状态。项目事务与总库事务独立，通过待同步记录和重试保持索引一致；总库离线不应丢掉项目的编辑。

练习：说明同一视频在两个项目中使用不同入出点时，分别写入哪个数据库和哪类记录。

## 第五步 学习长任务和交付

阅读 `main/services/file-job-registry.ts` 的窗口任务所有权，再追踪 `modules/delivery/package/export.ts`、`import.ts` 和 `infrastructure/jobs/file-jobs.ts`。

取消信号不会让所有资源瞬间消失：操作要先结束文件流、关闭数据库或探测线程，再清理专属临时目录。阅读文件任务的单元测试、`tests/support/file-jobs.ts` 和 ZIP 异常回归，理解之前 ENOENT 问题的防护。

## 第六步 学习预览和 BGM

从 `features/preview/PreviewView.tsx` 进入 `engine/audio-transport.ts` 和 `video-sync.ts`。音频上下文是共同时间基准；读取 / 解码期间画面等待，准备取消后不能启动旧音源。

画面只有实际播放、共同时间运行且未定位 / 缓冲时才校正漂移。对暂停画面反复定位会触发缓冲并取消 BGM 准备。结合音频 / 视频同步单元测试及 `scripts/smoke/professional.cjs` 的诊断阅读。

学习后尝试回答：一个按钮的事件在哪里、调用了哪个接口、哪个服务拥有事务、失败后谁负责恢复、对应验证在哪里。功能定位表可作为每次练习的索引。
