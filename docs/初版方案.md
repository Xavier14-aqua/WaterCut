# WaterCut 初版方案

> 状态：v1.0 起步的开发方案；目标平台：Windows 桌面端；原则：本地优先、单人可维护、可公开发布到 GitHub。后续阶段按 v1.0.1、v1.1、v1.2 等连续递增，目标版本和验收范围见 [技术落地路线图](./技术落地路线图-v1.md)。

## 1. 产品目标

WaterCut 帮助视频创作者把零散灵感整理成可编辑分镜，关联本地素材，并播放粗剪预览。第一版解决一条完整路径：

**创建项目 → 收集灵感 → 整理卡片 → 生成或手写分镜 → 关联素材 → 播放粗剪 → 保存和恢复版本。**

项目默认只保存在用户电脑上；不要求注册账号或租用服务器。AI 功能使用用户自行配置的服务密钥，并允许完全不配置 AI 时继续手工创作。

## 2. 第一版功能范围

| 模块 | 必须完成 | 验收标准 |
| --- | --- | --- |
| 项目 | 新建、打开、重命名、最近项目、自动保存 | 显示保存中/已保存/失败；关闭应用再打开，数据与素材关联不丢失 |
| 灵感箱 | 输入文字，导入图片、音频与视频，卡片可加标签和备注 | 素材可在项目中再次找到并打开 |
| 灵感白板 | 卡片拖动、连线、保存布局 | 重新打开后卡片位置和连线保持一致 |
| 分镜 | 手工创建、编辑、删除、排序；字段含画面、动作/对白、预计时长 | 纯离线状态也能完成一份分镜 |
| AI 草案 | 根据选中的灵感生成一版 5～10 镜头草案；用户确认后写入项目 | 模型失败或返回异常时不覆盖已有分镜 |
| 素材库 | 导入图片、视频、音频；缩略图、文件名/标签搜索；素材关联镜头 | 导入有进度和取消；移动原始文件不会使已导入素材失效；缺失素材可重新定位 |
| 粗剪预览 | 按镜头顺序播放一个主画面素材或展示文字占位；可调镜头顺序与时长 | 视频按入点/出点播放，图片按镜头时长展示；能从头至尾预览完整项目 |
| 版本 | 手动创建分镜快照并恢复 | 恢复前自动保留当前状态；恢复后镜头顺序和素材关联正确 |
| 项目备份 | 导出、导入项目包 | 可选择是否包含原始素材；在另一台电脑导入后能继续编辑 |

**语音转写**列为首版的可选扩展：先保证音频能导入和播放；如果 AI 服务支持转写，再加“转为文字灵感”操作。不要让转写阻塞主流程。

首版暂不做：三路线自动生成、分镜逻辑检查、素材语义搜索、BGM 节拍/情绪分析、正式成片导出、多人协作、云同步。本方案保留这些功能的数据接入位置。

首版粗剪约束：一个镜头可关联多个候选素材，但只指定一个主画面；视频的有效播放区间由入点和出点决定，图片及无素材镜头按镜头预计时长展示。音频素材首版可导入、播放和关联，但不参与连续粗剪；视频预览保留原声，不做独立 BGM 混音。若没有可播放的主画面，显示文字占位并继续播放下一个镜头。

首次启动无需配置 AI Key。自动保存必须给出状态；失败时保留未写入的编辑内容并允许重试。导入、生成、预览失败时提示原因和可执行的处理办法。

## 3. 技术栈

| 层 | 选择 | 说明 |
| --- | --- | --- |
| 桌面运行与打包 | Electron + Electron Forge | Windows 优先；使用 Forge 的 Vite + TypeScript 模板 |
| 界面 | React + TypeScript + Vite | 所有用户可见界面 |
| 灵感白板 | React Flow | 节点与连线交互；持久化使用 WaterCut 自己的数据格式 |
| 本地数据库 | SQLite | 保存项目、灵感、镜头、素材索引、关联和版本 |
| 媒体文件 | 项目目录中的普通文件 | 原件、缩略图、缓存分目录；数据库只记相对路径；显示项目占用空间 |
| 媒体处理 | Electron `nativeImage`；后续 FFmpeg / ffprobe | 首版用系统缩略图能力生成缓存并对不支持的格式回退预览；后续用 FFmpeg / ffprobe 做媒体校验、时长提取及更稳定的帧抽取 |
| AI | 可替换的 `AIProvider` 接口 | 首版实现一个提供商；输出经校验后作为草案展示 |
| 校验 | TypeScript 类型 + Zod | 校验 AI 输出、导入项目和 IPC 参数 |
| 测试 | Vitest + 少量端到端烟测 | 重点覆盖项目迁移、保存恢复、素材路径和版本恢复 |

SQLite 的 Node 驱动在开发前做一次**打包验证**：能在干净的 Windows 环境安装并读写数据库，再确定具体驱动。不要等到功能做完才发现原生模块无法正确打包。

## 4. 架构与数据

```text
React 界面
   │ 仅调用明确的、带类型的 API
Electron preload / IPC
   │
Electron 主进程 ── 项目服务 ── SQLite
   │             ├─ 素材服务 ── 项目文件夹
   │             ├─ AIProvider ── 用户选择的模型服务
   │             └─ 后台任务 ── FFmpeg / ffprobe
```

主进程负责文件、数据库、外部程序和密钥；渲染进程不直接操作 Node.js 文件系统。IPC 只暴露具体操作，例如 `createProject`、`importAsset`、`saveShot`、`generateShotDraft`、`createRevision`。耗时任务必须有状态、错误信息和取消入口。

Electron 启用进程隔离，渲染进程不开放 Node.js 集成；preload 只暴露白名单操作。IPC 输入、项目包内容和文件路径在主进程校验；导入项目包必须拒绝路径穿越、符号链接越界和超出预期的解压体积。AI Key 使用操作系统安全存储，不进入项目文件、导出包或日志。

核心数据对象：

- `Project`：名称、创建时间、项目格式版本（与应用版本分开）。
- `Idea`：文字、标签、来源素材、白板位置。
- `IdeaLink`：两个灵感之间的连线和备注。
- `Shot`：顺序、画面、动作/对白、预计时长、状态。
- `Asset`：类型、相对路径、时长、缩略图、标签。
- `ShotAsset`：镜头与素材的关联、是否为主画面，以及素材入点、出点。
- `Revision`：分镜和关联关系的快照、备注、创建时间。

建议项目结构：

```text
我的影片.watercut/
  project.sqlite
  assets/             # 导入的原始素材
  thumbnails/         # 可重新生成的缩略图
  previews/           # 可重新生成的预览缓存
```

导入素材时复制进项目目录，避免外部文件被移动后失效。导出项目包时通过数据库的备份机制生成一致快照，再连同素材打包；不要直接复制正在写入的数据库文件。缓存可在导出时省略。

素材导入先复制到项目内临时文件，校验类型、大小和可读性后再原子地放入 `assets/` 并提交数据库记录；失败或取消时清理临时文件，启动时可清理上次异常退出遗留的文件。导入前提示预计空间占用，识别项目内重复文件。导出包默认包含原始素材，允许用户选择不包含；不含原件的包须清楚标记为不完整备份。

数据库迁移按项目格式版本顺序执行：迁移前备份原项目；迁移失败时原项目仍可打开或原样保留；遇到高于当前应用支持的格式版本时禁止写入，并提示升级应用。恢复分镜快照前自动保存当前状态。项目包导入先在临时目录完成解压、校验和迁移，再放到目标位置，避免留下半成品项目。

## 5. 敏捷迭代

以“能实际完成一个用户动作”为迭代单位。每个迭代结束都要有可运行安装包或可演示构建；工期随开发人数和经验调整。

### 迭代 0：工程与打包验证

- 建立 Electron Forge + React + TypeScript 项目。
- 验证 SQLite 读写、项目目录、FFmpeg 调用、Windows 安装包及全新用户环境首次启动。
- 固定项目格式版本、迁移失败策略、IPC 安全边界和项目包导入规则。
- 锁定依赖；建立 Windows CI：类型检查、构建、关键测试和安装包构建；加入 Issue 与 PR 模板。
- **完成条件**：在干净的 Windows 环境安装，无需 AI Key 即可创建项目、重启后读回；模拟旧版项目迁移失败，原件不受损。

### 迭代 1：离线创作闭环

- 灵感箱、手工分镜、带状态的自动保存、原子素材导入和关联。
- 按首版粗剪约束实现顺序预览，处理入点/出点、图片时长和缺失素材。
- **完成条件**：不用 AI 也能做出一份可播放分镜。

### 迭代 2：白板与 AI 草案

- 灵感卡片拖动、连线；选中灵感生成镜头草案。
- 草案先预览、可编辑，确认后再加入分镜；模型失败有明确反馈。
- **完成条件**：一条灵感能生成并修改 5～10 个镜头，原项目始终可恢复。

### 迭代 3：可发布版本

- 手动版本快照、安全恢复、项目导入导出及包校验。
- 处理丢失文件、无效媒体、升级迁移和异常退出后的恢复。
- README、安装说明、隐私说明、许可证与依赖许可证核对、版本号和变更记录；发布 Windows alpha。
- **完成条件**：自己用真实素材完成一个项目，并在另一台 Windows 电脑导入继续编辑。

## 6. GitHub 开源与质量门槛

- 仓库包含 `README.md`、`CONTRIBUTING.md`、`LICENSE`、问题模板和最短复现步骤模板。正式选许可证前核对所用组件及 FFmpeg 打包方式的许可要求。
- 仓库提交依赖锁文件，记录 FFmpeg 获取来源、版本与分发方式；发布安装包应能从标记的源码版本复现构建。
- 不上传用户素材、项目数据库、API Key 或日志中的敏感内容；示例项目只用有权公开的素材。
- 每个 PR 至少通过类型检查、构建与对应功能的关键测试。涉及数据库结构的 PR 必须附迁移和旧项目打开验证。
- 发布前在全新 Windows 用户环境验证：首次安装、无 Key 创作、新建项目、重启恢复、导入中断、磁盘空间不足、缺失素材、粗剪预览、AI 失败、版本恢复、旧项目迁移、项目导入导出及异常项目包拒绝。
- 收集 Issue 时区分：崩溃/数据丢失、安装问题、媒体兼容、AI 服务问题、功能建议。优先修复数据丢失和无法打开项目。

## 7. 下一步具体任务

1. 初始化工程，并完成“安装包 + SQLite + 项目目录”技术验证。
2. 固定项目数据格式和迁移策略，写出第一个项目保存/打开流程。
3. 用你自己的一个真实视频项目持续试用；每次迭代优先修最阻碍创作的一步。

**第一条可交付用户故事**：作为创作者，我能新建项目、写三个镜头、关闭 WaterCut、重新打开并看到同样的内容和顺序。
