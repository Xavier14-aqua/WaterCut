## 2. 实现前先固定的数据规则

1. **原件不被剪辑修改。** 导入时复制到用户的受管素材库；视频入出点、候选关系和项目备注只写项目数据库。每条镜头素材绑定都有自己的裁剪范围。
2. **原件按内容去重，创作记录不强制合并。** SHA-256 相同可以复用同一物理文件；两张文字相同的灵感卡仍可能是不同记录，不能仅按内容自动合并。
3. **项目灵感使用内容快照。** 引用全局卡片时记住来源 ID、来源版本和当时内容。项目内修改不回写总库；全局卡变化时提示可比较和更新，由用户选择。
4. **原件内容一旦登记就保持不变。** 重新定位应校验原件哈希；改用不同内容的文件应创建新素材版本或新素材记录，避免所有引用和旧快照悄悄换片。
5. **已有项目内素材仍有效。** 继续支持项目自带副本；升级不要求先加入全局库，也不把用户素材自动移动到新库。独立项目包解包后可无全局库运行。
6. **全局灵感关系与项目白板连线分别存储。** 全局关系表达内容关联；白板连线表达某项目的构思。白板里有分叉、环路时，不能直接推断唯一镜头顺序。
7. **脚本、分镜、时间轴共用镜头事实。** 镜头画面、对白、排序和裁剪各有一个保存位置，视图只是不同编辑入口；时间轴不额外保存另一份镜头顺序。
8. **缺失、未使用、待拍是不同维度。** 媒体健康状态由文件检查得出；是否使用由镜头关联计算；拍摄/创作状态由用户维护，不能都塞进一个枚举字段。
9. **项目数据库是项目事实来源。** 全局项目大厅、使用次数是可重建索引；跨数据库操作通过可重试任务和 outbox 对账，不假定几个数据库加媒体文件能用一次事务提交。
10. **快照不能替代备份。** 快照保存可恢复的编辑状态；含所需原件的项目包用于完整迁移。只有数据库、没有原件的快照无法恢复已经彻底删除的媒体。

## 3. 建议目录与模块边界

源码保持在 `WaterCut/`。开发默认项目目录继续使用仓库旁的 `WaterCut Projects/`；新增全局库可默认使用同级的 `WaterCut Library/`。仓库外运行的 ZIP 分别默认使用用户文档下的这两个目录，可在设置中修改。

```text
WaterCut/                         源码、测试、配置、文档
WaterCut Library/                 用户全局库，可在其他磁盘
  library.sqlite                  素材、灵感、标签、项目索引
  objects/ab/<sha256>.mp4          受管原件；ab 为哈希前两位
  thumbnails/                     可重建缓存
  jobs/                           任务恢复信息或临时文件
WaterCut Projects/
  <project-id>.watercut/
    project.sqlite                项目镜头、引用、脚本、布局、快照
    assets/                       项目独有原件、打包带来的独立副本
    thumbnails/                   项目局部缓存
应用 userData/
  storage-settings.json           目录和当前库 ID 等本机设置
  ai-settings.json                现有加密 AI 设置；不进入项目包
```

便携 ZIP 指应用无需安装；默认情况下本机配置与密钥仍属于当前 Windows 用户，不随 ZIP 一起迁移。

目标代码布局分步形成，先搬出已有逻辑并保证行为不变，再增加功能：

```text
src/
  main.ts                         应用生命周期与服务装配入口
  preload.ts                      白名单 API
  shared/
    models.ts                     纯类型，不导入数据库和文件模块
    schemas.ts                    Zod 输入/输出校验
    contracts.ts                  请求、响应、事件类型
    duration.ts                   时长与时间轴计算
  main/
    settings.ts                   本机目录配置
    ipc.ts                        IPC 路由与会话检查
    db/                           连接、迁移、备份、事务
    library/                      全局灵感与素材服务
    project/                      项目、脚本、镜头、快照服务
    media/                        导入、哈希、探测、缩略图、协议解析
    jobs/                         任务状态、取消、重试、outbox
    export/                       项目包、PDF、时间线适配器
    ai/                           提供商、草案、确认应用
  renderer/
    shell/                        导航、项目大厅、四区布局
    library/                      灵感与素材浏览
    board/                        复用现有 IdeaBoard
    script/                       文档和双栏脚本
    storyboard/                   分镜卡片/清单
    preview/                      播放器、时间轴
    inspector/                    当前选中对象与 AI 抽屉
    state/                        会话、选中状态、保存队列、实体缓存
```

保留根入口文件，避免一开始同时改动所有 Forge 入口。`project.ts` 可先作为兼容门面逐步转发。本路线不要求更换 Electron、React、SQLite、React Flow，也不要求引入后端服务器。

## 4. 阶段 0（v1.0.1）：存储配置、数据契约与迁移基础

### 0.1 设置目录并持久化

任务 `S0-01`：在新建项目页/设置页提供“项目保存位置”和“全局库位置”。通过主进程文件夹对话框选择，检查绝对路径、可读写、库标记与磁盘可用性后保存；配置写临时文件再替换，保留可恢复的上一个版本。配置带 `configVersion`。

```ts
type StorageSettings = {
  configVersion: 1;
  projectsRoot: string;
  libraryRoot: string;
  activeLibraryId: string | null;
};
```

改默认项目目录只影响后续新建项目，既有项目按已登记路径打开。全局库切换为明确操作：打开另一库，或另建迁移任务复制整个旧库。迁移任务先复制/备份、校验哈希与数据库，再切换配置；保留源库到用户确认清理。目录不可用时显示重选入口，不静默新建一个空库掩盖问题。

建议 IPC：`settings:get-storage`、`settings:choose-project-root`、`library:open`、`library:relocate`；主进程负责对话框和路径解析。

### 0.2 抽离共享类型、会话和保存命令

任务 `S0-02`：把 `project.ts` 中 DTO/Zod 移入 `shared/`，界面只引用纯类型。项目返回持久化的 `project.id`，增加编辑修订号 `contentRevision`，不再用目录当唯一项目身份。

新接口建议采用以下约定：

```ts
type Command<T> = {
  sessionId: string;              // 主进程登记的当前库/项目会话
  commandId: string;              // 去重与重试
  expectedRevision: number;
  payload: T;
};
type Result<T> =
  | { ok: true; data: T; revision: number }
  | { ok: false; code: string; message: string; retryable: boolean };
type JobProgress = {
  jobId: string; scopeId: string; phase: string;
  completed: number; total: number | null;
};
```

按数据集分页读取，变更返回修改的实体与修订号，避免每次编辑把全库重新加载。旧接口可在兼容层继续返回完整项目，迁移期间保持可运行。

主进程验证会话、对象归属与 Zod 输入；媒体操作从登记的 ID 解析文件，不接受界面拼出来的任意磁盘路径。切换项目取消旧会话的订阅和未应用任务；已经开始的磁盘任务按任务归属完成或取消，不能把结果写进新项目。

保存保留现有延迟合并思路：每实体串行排队，带本地编辑序号；旧请求成功不能覆盖更新的界面输入。发生修订冲突时保留本地草稿并提示重新应用。内容提交后才标记“已保存”；缩略图完成不代表正文保存成功。应用退出沿用现有等待保存机制，并提供失败重试。

### 0.3 数据库迁移与一致备份

任务 `S0-03`：为全局库、项目数据库分别维护格式版本。项目从现有 v7 顺序迁移，实际版本号在各功能合入时分配，不提前一次跳到终版。每个连接明确设置/检查外键支持、忙等待和事务策略；不假定默认值。旧数据先做引用检查，清理策略必须可追溯。

迁移流程：识别有效项目 → 暂停该项目写入 → 一致备份 → 在副本演练/检查 → 执行受控事务迁移 → `integrity_check` 和 `foreign_key_check` → 发布新版本连接；失败则回滚并保留原件和备份。版本更高的项目拒绝写入。

备份统一封装，优先验证 `node:sqlite.backup` 在打包后的 Electron 中可用，或采用经验证的 SQLite 备份方式。SQLite 官方提供在线备份与 `VACUUM INTO` 途径，不能把活动数据库的一次普通文件复制当作通用备份方案。[SQLite 备份文档](https://www.sqlite.org/backup.html)

### 0.4 后台任务与工程验证

任务 `S0-04`：哈希、媒体处理、库扫描和大型查询放后台任务。`DatabaseSync` 的大查询计划放到专用 Node worker；主进程保留窗口、对话框和 IPC。每个数据库写命令串行处理；可先用单 worker 管理连接，遇到明确性能瓶颈再拆。

worker 先做小范围打包验证：新增明确构建入口，生成可定位的 CJS 产物，验证开发模式、`app.asar` 和 ZIP 中都能创建 worker；不直接在运行时加载 `.ts`。建议在多窗口开放前统一写入队列，当前阶段可限制单应用实例。

任务统一有 `queued/running/cancelling/succeeded/failed/cancelled`、持久化阶段与 `jobId`；只有耗时且可恢复的任务需要持久记录。取消复制清理临时文件；提交已经成功则报告完成，不把它误报为取消。

**完成条件**：重启后目录设置仍在；旧项目可打开；新建项目不进入仓库；保存冲突不丢草稿；迁移失败不破坏原库；worker 在真实 ZIP 内可运行。

## 5. 阶段 1（v1.1）：全局灵感/素材库和项目引用

### 1.1 建立全局库与项目大厅

任务 `S1-01`：新增 `library.sqlite`，每个库有独立 UUID。先支持一个活动全局库，保留 `libraryId` 为未来切库和跨库识别准备。

建议表及主要字段：

| 表 | 主要字段 | 约束/用途 |
| --- | --- | --- |
| `library_meta` | id、format_version、created_at | 标识真正的 WaterCut 库 |
| `blobs` | sha256、relative_path、size、state | 原件不可变；哈希唯一 |
| `assets` | id、blob_sha256、kind、name、imported_at、captured_at、metadata_json、starred、hidden_at、version | 素材条目；拍摄时间可空，不能冒充导入时间 |
| `ideas` | id、kind、text、notes、payload_json、recorded_at、occurred_at、time_source、version、hidden_at | kind 为 note/mood/scene，保留快速文字记录 |
| `idea_media` | idea_id、asset_id、role、position、in_ms、out_ms | 参考图、参考音频/视频，顺序和可选片段 |
| `tags`、`idea_tags`、`asset_tags` | 规范化标签与关联 | 不继续依赖逗号字符串做精确关联 |
| `idea_relations` | id、source_id、target_id、relation_type、note、created_at | 已确认的全局关系；按类型规定有向/无向 |
| `project_catalog` | project_id、path、name、archived_at、last_seen_at、availability、indexed_revision | 已登记项目大厅；不是项目正文来源 |
| `usage_index` | project_id、entity_kind、global_id、shot_id、role、indexed_revision | 可重建的已知项目使用缓存 |
| `operations` | operation_id、kind、stage、mapping_json、error | 跨库任务恢复和幂等映射 |

常用索引：素材哈希、素材种类/导入时间、灵感记录时间、标签 ID、关联两端、项目 ID；列表游标排序使用 `(时间,id)`，避免翻页结果跳动。项目归档只改大厅/项目元数据，不删除素材。

### 1.2 导入素材并去重

任务 `S1-02`：复用现有流式复制、SHA-256、空间检查、取消与临时文件清理，但把去重哈希存入库，避免每次导入都重新读取同大小的所有原件。

导入顺序：选来源 → 预检查大小/空间 → 流式复制到目标盘临时目录并算哈希 → 校验读取与媒体类型 → 找已存在 blob → 原子发布新 blob 或复用已存在 blob → 事务写素材条目 → 异步生成缩略图。失败保留可恢复阶段；未登记原件在任务恢复/对账后处理，不能按“数据库查不到”立即删除。

内容相同但名称不同的文件默认提示已存在素材，可选择引用旧条目；需要不同创作归档信息时允许新条目复用原件。重复文本卡片不会自动合并。

第一阶段延续现有系统缩略图与浏览器预览。媒体时长先从可播放元素获取并标记来源/探测状态；无法探测就显示未知，不把失败填成 0。阶段 3 做精确交付前补齐离线媒体探测；未知数据不能用于承诺准确的视频时间线。

### 1.3 情绪卡和场景记录

任务 `S1-03`：公共字段为文字、标签、备注、记录时间、附件；专用字段用有版本的 Zod 联合类型校验，再保存到 `payload_json`。

- 情绪卡：1～3 张可选参考图、颜色条、情绪标签、可选参考音频和节奏备注。允许只先记一句话，稍后补图，不能因为缺图阻断记录。
- 场景记录：昼夜/天气/环境、地点文字、关键道具、动作/对白片段、参考短视频或音频；地点手填，不默认获取定位权限。
- 颜色条：后台解码缩略图并缩小取样，以量化/聚类取数个主色并缓存；失败不阻断保存，允许手动选色。
- 时间：`recorded_at` 自动记录；`occurred_at` 是用户确认的发生时间。历史项目没有原始记录时间时标记来源未知或导入时间，不捏造旧日期。

任务 `S1-04`：实现时间线/标签列表和关联抽屉。年/月/周是按明确的用户时区分组，周起始日固定并在界面一致。标签精确检索先完成；文本子串搜索使用参数化查询并转义通配符。候选自动关联可按共同标签和时间距离排序，逐条显示推荐理由，用户点确认才写入 `idea_relations`。

全局量大后再启用 FTS5 与分页。中文搜索必须实测一字、二字、三字和混合文本；trigram 全文查询对不足三个 Unicode 字符有局限，短查询保留标签/子串回退，不把启用 FTS5 当成已解决中文分词。[SQLite FTS5 文档](https://www.sqlite.org/fts5.html#the_trigram_tokenizer)

### 1.4 项目引用和内容隔离

任务 `S1-05`：对现有项目表做兼容扩展，保留原 ID 和已有镜头关联。

| 项目对象 | 建议新增字段/表 | 行为 |
| --- | --- | --- |
| `assets` | storage_kind、source_library_id、source_asset_id、blob_sha256、metadata_snapshot | 本地副本或全局引用；本地 relative_path 允许在引用模式下为空 |
| `ideas` | kind、payload_json、source_library_id、source_idea_id、source_version、内容快照字段 | 引用后是一张项目自己的卡片；x/y 继续项目局部保存 |
| `idea_media` | 项目 idea_id、项目 asset_id、role、position | 附件引用也要进入项目，不能只复制文字 |
| `board_edges` | relation_kind、label、direction | 保留原连接点，新增连线含义 |
| `shot_sources` | shot_id、project_idea_id、source_excerpt | 镜头来源，可多对多；灵感删除后仍保留来源摘录 |
| `outbox` | event_id、project_revision、payload、delivered_at | 项目事务中记录待同步使用索引事件 |

媒体解析器：优先使用该项目合法本地副本；否则按 `libraryId + assetId + blobSha256` 找受管原件。不同内容的同名文件不是同一素材。库离线时项目文字仍能编辑，引用媒体显示缺失并保留原时间信息。

从总库拖进项目：读取全局卡片当前版本 → 建项目内容快照和项目媒体引用 → 复制选中卡片间的已确认关系为项目白板连线 → 在一次项目事务中写入 → 通过 outbox 更新大厅/使用缓存。拖入相同卡片时允许“定位现有实例”或“再建实例”，不按全局 ID 强制共享项目排版。

### 1.5 升级已有项目、防误删和首次体验

任务 `S1-06`：默认只升级数据结构，旧原件继续在项目 `assets/`。提供独立的“加入全局库”任务：以 `projectId + 旧实体 ID + targetLibraryId` 记录映射，先复制和校验全局原件，再提交项目来源引用，最后对账；成功后也不自动删除原项目副本。中断后能继续，同一次任务不会重复创建多张卡。

任务 `S1-07`：项目删除引用只删本项目实例；全局隐藏只影响总库展示。全局永久删除必须展示已登记项目和快照依赖，索引不全或项目离线时说明无法确认完整范围，默认阻止自动清理。v1 先提供隐藏，不提供后台自动删除原件。

使用缓存统计的是“已登记且已索引的项目”，不能声称已扫描整个磁盘。打开/保存/恢复项目后对账，外部移动或拷贝的项目通过重新登记补全。发现同 projectId 对应多个路径时要求选择迁移位置或创建副本身份，避免使用次数错算。

任务 `S1-08`：提供可跳过的官方示例项目；示例素材有可分发权利，作为应用只读资源，首次使用时复制为用户可编辑项目，不能把开发者真实项目当示例。此项界面可在阶段 2 完成后接入。

建议 IPC：`library:list-ideas`、`library:create-idea`、`library:import-assets`、`library:list-assets`、`library:find-related`、`library:confirm-relation`、`project:attach-ideas`、`project:attach-assets`、`project:promote-to-library`、`project:list-catalog`。导入返回 jobId，并订阅该任务进度。

**完成条件**：不打开项目也能录入两类卡片和素材；A/B 项目引用同一原件而裁剪/备注互不影响；库隐藏不使项目失效；旧 v7 项目离线可用；全局导入取消、迁移中断可恢复；总库与源码目录完全分开。

## 6. 阶段 2（v1.2）：四区布局与白板→脚本→分镜→粗剪

### 2.1 拆分工作台和状态

任务 `S2-01`：将 `App.tsx` 逐步拆成 ProjectHall、WorkspaceShell、ResourceSidebar、Inspector、AIDrawer 与各视图。顶栏使用白板/脚本/分镜/粗剪/清单五个入口；三个核心视角与额外流程入口并存，不需要为每个标签复制数据。

资源栏切换“当前项目/全局总库”，浏览范围只影响列表；拖入全局对象时显式创建项目引用。检查器根据 `{kind,id,scope}` 展示当前选中对象，不由多个组件各自维护一份选中内容。

初期采用 React context + reducer 保存会话、实体缓存和 selection；保存队列抽 hook。视口、面板宽度等 UI 配置与项目正文分开；项目白板节点坐标属于项目内容，不能仅放 localStorage。大列表分页与虚拟渲染，缩略图继续懒加载。

### 2.2 白板到镜头骨架

任务 `S2-02`：扩展现有 React Flow 节点，显示情绪/场景卡片、参考图和来源；支持分区和连线文字。鼠标拖动时只更新界面位置，拖动结束再提交；连线标签编辑按保存队列处理。

“转为分镜”先显示顺序预览：选中卡片若构成单链，沿明确方向排序；有分叉、环或不相连时，让用户在列表中确认顺序，不能靠坐标随意猜。支持手动排序后确认，提交明确的 `orderedIdeaIds`。

手工路径在一个事务中创建镜头、默认时长和 `shot_sources`；使用 `commandId` 防重复点击。新镜头允许画面字段暂空，卡片原文进入来源摘录；需要扩展当前“画面非空”的校验，草稿与可交付状态分别校验。AI 路径沿用草案预览，确认后同样一次性创建来源与镜头。

### 2.3 双态脚本，先做可控的一对一同步

任务 `S2-03`：新增 `script_blocks(id,position,kind,draft_text,shot_id)`。纯文档模式按稳定 block ID 保存段落；未转镜头段落保存在 `draft_text`。v1 一个正文段落可在确认时转成一个镜头，标题/备注不自动转镜头。

转换后 `shot_id` 指向镜头，关联段落的正文从 `shots.action_dialogue` 投影显示，`draft_text` 不再保留另一份可编辑正文；双栏右侧也编辑这个字段，左侧编辑 `shots.description`。现有“动作/对白”混合文本原样保留，不自动声称它已经被拆成纯声音脚本。

切视图只改变渲染方式，不运行文字重新切分算法。已有镜头首次打开脚本视图时创建 block 映射，顺序以 `shots.position` 为准；未关联草稿段落有独立文档位置。删除关联段落/镜头、拆分/合并都要预览受影响对象并事务提交。需要多段落对应多镜头时再扩展映射，不在首版暗做双向自动推断。

### 2.4 分镜、拖拽绑定和待拍清单

任务 `S2-04`：故事板/表格读取同一组 shots。扩展字段 `scene_id/scene_text`、`shot_size`、`camera_movement`、`production_status`、`needs_review`、`review_note`。production_status 可采用 idea/written/to_shoot/ready/locked；媒体 available/missing/unplayable 单独计算。

资源拖拽只传 `{scope,entityId}`，主进程校验后创建项目素材实例并加入候选。允许多个候选，一个主画面；取消主画面不能误删原件。裁剪写镜头绑定而非全局 asset。更换主画面重置该绑定裁剪，或显式采用已选子片段。

待拍清单按“用户标记待拍 + 没有可用主画面的镜头”派生，保留两种原因；按场景和昼夜分组，提供打印/CSV。画面或素材缺失不应自动覆盖用户已定稿状态，而应额外报警。

### 2.5 统一时长和粗剪播放状态机

任务 `S2-05`：新增纯函数 `buildPreviewSequence` 与 `effectiveDurationMs`，播放器、时间轴、总时长和后续导出共用。时间区间统一为 `[inMs,outMs)`：入点包含、出点不包含。

```text
视频主画面且裁剪信息可解析：
  resolvedOut = 明确出点，或媒体已知时长
  effectiveDuration = resolvedOut - inMs
图片/无视频主画面：effectiveDuration = shot.durationMs
视频时长未知或裁剪无效：标记待检查，预览使用预计时长占位
```

若媒体文件暂时缺失但保留有效时长/裁剪元数据，可用原视频区间时长播放文字占位，保持节奏；否则退回预计时长并提示。无素材占位展示画面描述和动作/对白，不只是“暂无素材”。

视频片段由播放器 seek 到入点；图片和占位使用统一播放时钟。实现 idle/loading/playing/paused/seeking/ended/error，监听 loadedmetadata、seeked、ended、error，记录等待状态与超时。时间线定位用全局时间减片段起点，再加源入点；图片/占位暂停后不能继续累计时间。

现有 timeupdate 切镜适合粗剪；可结合动画时钟/视频帧回调改善 UI 更新，但不承诺因此实现逐帧剪辑。加载失败、格式不支持或 seek 超时应进入可见错误/占位分支，不能无限卡住整个预览。

任务 `S2-06`：时间轴先用 DOM/SVG 绘制一条镜头轨。每个色块直接投影镜头顺序和有效时长；拖动交换在结束时提交 `reorderShots(orderedIds)`，校验 IDs 无遗漏、重复、外来镜头。拖拽边缘：图片/占位改预计时长，视频改该绑定入/出点；统一最短时长并检查媒体上限。播放中完成排序/裁剪后暂停并按稳定 shotId 重新定位。

“待优化标记”保存 `shotId + note`；需要片内位置时另存 offsetMs，不存会随前面镜头长度变化的绝对全片时间。

建议 IPC：`script:save-blocks`、`script:convert-to-shots`、`shot:create-from-ideas`、`shot:reorder`、`shot:update-metadata`、`shot:update-trim`、`shot:mark-review`。来源、排序和正文变更都在项目命令事务中更新修订号。

**完成条件**：离线、不配 Key，能从全局卡片创建项目并得到手工镜头；脚本/分镜中编辑同一句对白即时一致；三个视角和清单不产生重复正文；视频/图片/无素材混播可暂停与定位；重启后排序、裁剪、来源、标记全部保留。

## 7. 阶段 3（v1.3）：快照、项目包、PDF 与分发验收

### 3.1 快照与恢复

任务 `S3-01`：新增 `revisions(id,name,created_at,document_version,payload_json)`，保存项目局部内容：卡片快照、脚本块、连线、镜头、候选、主画面、裁剪、来源、状态。使用全量 JSON 起步，按实际体积再考虑压缩/增量；历史快照中不嵌套所有旧快照。

另建 `revision_media_refs(revision_id,asset_id,blob_sha256,locator_snapshot)`，保存当时素材描述与原件指纹，作为依赖保留依据。普通删除素材实例只从当前编辑状态移除，不能立即物理删除仍被快照引用的原件；全局 blob 与项目局部文件都要有保留/回收策略。

创建快照先完成待保存编辑，再读取同一版本的一致内容。恢复先自动创建当前状态快照，校验目标结构并升级旧快照格式，在事务内恢复实体和关系、增加新的 contentRevision，再重建使用缓存。不会把整个数据库降回旧 schema。找不到历史媒体时恢复文字和关联描述，明确显示缺失。

**关键测试**：恢复前自动快照；恢复后顺序、对白、白板和裁剪一致；当前删掉的素材在保留原件时仍可从旧快照恢复；恢复失败不出现一半新一半旧。

### 3.2 可独立打开的项目包

任务 `S3-02`：定义 WaterCut 项目包格式及 manifest。至少包含包版本、项目格式版本、项目 ID、内容文件清单、尺寸与 SHA-256、是否包含媒体/历史、缺失媒体清单。路径只用包内相对路径，不泄露原用户绝对路径。

导出顺序：完成保存 → 固定项目内容版本并短暂排队编辑 → 用数据库备份 API 得到一致项目快照 → 枚举该快照引用的媒体依赖 → 对源 blob/项目原件加任务保留标记 → 复制去重原件到 staging → 把导出副本的全局引用改写为项目本地相对路径 → 校验 → 写 manifest → 打包为临时文件 → 成功后发布目标文件并释放保留标记。

只导出当前状态时无需带无关全局素材；选择带历史时，依赖闭包还要包含所选历史快照引用的原件。项目局部灵感附件、参考音频、候选素材也属于依赖，不能只打包主画面。

默认包含全部所需原件。选择不包含或源文件已缺失时，包应明确标为不完整，不显示“完整备份成功”。取消或磁盘不足时清理 staging，不改写用户原项目。

任务 `S3-03`：导入到目标盘临时目录：校验 manifest 和版本 → 检查文件路径、条数、逐文件/总解压大小 → 流式解压并校验哈希 → 只读检查 SQLite → 受控迁移 → 所有引用校验通过后发布新目录。拒绝绝对路径、`..`、符号链接、Windows ADS/保留设备名、大小写冲突和重复条目，不能让 ZIP 内容写到 staging 外。

同 projectId 已存在时默认“导入为副本”：创建新项目身份，保留来源身份信息，不覆盖旧项目；明确选择恢复/替换时才走备份替换流程。包导入后先作为独立项目打开，加入全局库是另一步可选操作，不能自动把不可信来源关联到本机相同 ID 的原件。

**关键测试**：一台没有全局库的另一 Windows 电脑能打开完整包；中文路径和同名素材正常；恶意路径包拒绝且目标目录不变；导出/导入中断不留下伪完整项目。

### 3.3 稳定媒体元数据和 PDF 分镜表

任务 `S3-04`：交付前补齐后台媒体探测。以现有系统缩略图作为回退；引入 ffprobe/必要的 FFmpeg 时，先选择可分发构建，核对其具体许可证和随包资源，不从环境 PATH 假定陌生用户已安装。固定版本和校验值，通过 `spawn(executable,args,{shell:false,windowsHide:true})` 启动，设置超时/取消和输出大小上限。

媒体元数据保存 duration、宽高、视频/音频流、帧率分子分母、time_base、编解码信息、探测状态；变帧率素材需按实际时间戳处理，不能把 avg_frame_rate 当成每帧精确映射。未知/不可解码素材保留原件与错误，不能仅靠扩展名判定可播放。ffprobe 可输出机器可读的容器/流信息，按其 JSON 输出校验。[ffprobe 官方文档](https://ffmpeg.org/ffprobe.html)

任务 `S3-05`：PDF 采用独立受控打印页面，由项目 DTO 渲染缩略图、序号、画面、动作/对白、景别/运镜、时长、状态和来源。使用本地资源、打印 CSS 和中文字体，Electron 隐藏窗口 `printToPDF` 输出；标题/正文转义，避免把用户文本直接拼成可执行 HTML。

明确 A4 横/竖版、页眉页码与行跨页规则；长对白可拆续行，不能被固定卡片高度裁掉。待拍清单复用同一导出 DTO，可输出分组 CSV/打印页。图片缺失显示占位，导出前列出问题。

### 3.4 发布与数据隔离

任务 `S3-06`：继续用 Electron Forge MakerZIP；CI 运行类型检查、关键数据测试、迁移/包测试和构建。ZIP 检查需覆盖 `app.asar` 内部，确认没有个人 `.watercut`、库数据库、AI 设置、临时文件和真实素材。官方示例是经过明确许可的独立白名单资源。

重新计算 ZIP SHA-256；以生成这份 ZIP 的源码提交和锁文件记录构建。类型检查/构建通过后，在全新 Windows 用户环境验证首次启动、无 Key 离线创作、路径设置、退出重开、缺失素材、恢复、项目包搬家。软件签名、自动更新可独立排期，当前分发形式保持免安装。

建议 IPC：`revision:create/list/restore`、`project:export-package`、`project:import-package`、`export:storyboard-pdf`、`export:shot-list`、`job:cancel`。

**完成条件**：在另一台电脑无需开发环境/全局库即可运行 ZIP 并打开完整项目包；快照可恢复；PDF 可阅读/打印；源码与 ZIP 均无个人数据。此时才把相应功能标记为完成。

## 8. 阶段 4A（v1.4）：专业创作扩展

### 4A.1 精华子片段与素材复用足迹

任务 `S4-01`：新增全局 `selects(id,asset_id,name,in_ms,out_ms,note,version)`，只保存原件区间，不生成新视频文件；检查 `0 <= in < out <= duration`，未知时长时先完成探测。项目使用时复制区间到自己的镜头绑定并记录 sourceSelectId/version；之后总库修改 select 不改变旧项目裁剪。

任务 `S4-02`：从项目 outbox 与已登记项目扫描重建 `usage_index`，按素材和区间显示项目名、镜头号、角色、最后核对时间。主画面使用、仅候选、参考音频应分别统计；同镜头重复关联不能重复计数。若多个 selects 区间重叠，给出提示但允许创作者继续；离线/过期索引显示数据范围，不显示虚假的全盘准确总数。

### 4A.2 BGM 与拍摄清单增强

任务 `S4-03`：新增 `audio_clips(id,asset_id,timeline_start_ms,in_ms,out_ms,gain,fade_in_ms,fade_out_ms)`。音频仍引用受管原件；以同一预览时钟驱动播放/暂停/seek，调节视频原声与 BGM 音量；输出设备切换、加载迟延和后台节流做实际验证。Web Audio 等方案先做同步原型，不承诺单靠两个独立播放器能长期同步。

完善待拍清单的场景、昼夜、道具、已拍/缺口标记；导出与界面使用同一筛选结果，手动状态与媒体健康提示继续区分。

### 4A.3 一种目标剪辑软件的时间线交接

任务 `S4-04`：先定义应用内部 `TimelineDocument`：序列帧率的有理数、画布尺寸、片段顺序、源文件映射、源入出点、轨道与音量。WaterCut JSON 只用于自身交换；外部剪辑软件交接由独立适配器实现。

先选择一个目标软件及具体版本，用公开的实际导入规范和样本工程做验证，随后再确定 FCPXML、OTIO 或其他格式。不能宣称某个“通用 JSON/XML”天然兼容剪映、Premiere 和达芬奇。

第一轮限定单视频轨/直切/有限音频；生成素材包与路径清单。帧转换由统一模块计算边界，避免逐片段四舍五入累积误差；变帧率与不支持媒体需先规范化或给出明确不支持结果。无素材占位必须约定生成占位媒体还是交接标记，不能悄悄丢片段。

验收在目标软件真实导入：检查总时长、镜头数、中文路径、图像时长、入出点、音频和离线媒体提示，再扩大支持格式。

### 4A.4 AI 的四类建议

任务 `S4-05`：在已有 AIProvider 基础上按任务定义类型：路线大纲、配画面建议、分镜检查、灵感回声。响应结构经 Zod 校验并关联输入对象 ID、基准 projectRevision、状态与取消入口。

- 路线大纲返回 2～3 个独立候选，用户选一个再创建脚本/镜头，不修改现有稿。
- 配画面返回右栏段落对应的建议，逐条采纳后更新目标画面字段；采纳前检查该字段是否已被用户修改。
- 分镜检查返回 `{shotId,issueType,explanation,suggestedAction}`，以批注展示。补镜先生成草案，确认后用项目命令插入。
- 灵感回声先复用阶段 1 的本地标签/时间候选，静默展示在抽屉。若调用远程模型，需另有明确开关和发送范围说明，不能因“自动触发”默认上传总库。

网络失败不改正式项目。待确认草案可按需本地保存为 proposal，Key 继续放 safeStorage；日志不包含密钥或完整私人请求。实际模型支持、费用和参数在接入时按所选服务验证，不把文档示例当成固定服务承诺。

**完成条件**：精华区间复用互不污染；使用足迹可核对；BGM 随预览同步；目标软件导入通过；AI 建议拒绝、过期或失败时原稿保持可恢复。

## 9. 阶段 4B（v1.5）：研究与迭代

1. **分支版本**：在 revisions 上增加父节点和 branch head，先做从快照分叉、两个分支切换和字段差异比较。以实体 UUID 比较正文/排序/裁剪；自动合并只处理无冲突修改，冲突由用户解决。原件按快照依赖继续保留。
2. **语义素材搜索**：后台按镜头或固定片段抽帧、生成文字描述/向量，索引记录 blobHash、区间、模型版本。先建立中文查询集和标签检索基线，评估召回与误检，再确定向量索引方案。原件不变时可复用结果；新模型版本可重建。远程分析需要用户明确启用和可见范围。
3. **BGM 节拍/情绪曲线**：对音频特征后台分析并缓存，返回带置信度的时间点；允许移动/删除节拍点。建议吸附不应自动重排已有镜头。
4. **语音转文字灵感**：录音或导入 → 后台转写任务 → 分段文字和时间戳草案 → 用户确认建卡。来源音频和区间保留，转写可取消/重试；无网络时支持继续保存音频便笺。

这些功能以小样本原型和真实数据效果为先，不在阶段 1 提前引入向量服务、复杂模型流水线或分支合并系统。

## 10. 推荐开发顺序和发布门槛

建议每项形成能审查的独立改动：

1. `S0-01..04`：目录设置、共享类型/命令、迁移备份、后台任务打包验证。
2. `S1-01..02`：全局库和受管素材导入，先验证一个原件跨两个项目。
3. `S1-03..04`：两类卡片、时间/标签检索和关联抽屉。
4. `S1-05..07`：项目引用、已有项目加入全局库、删除/隐藏与对账。
5. `S2-01..02`：拆工作台、白板手工转镜头；跑通无 AI 路径。
6. `S2-03..04`：脚本投影、分镜双视图与待拍清单。
7. `S2-05..06`：统一时长、播放状态、时间轴编辑和标记。
8. `S3-01..03`：快照和独立项目包，先验证跨电脑恢复。
9. `S3-04..06`：元数据、PDF、示例项目、ZIP 与干净环境验收。
10. 达到前述门槛后进入 `S4-*`；外部时间线适配先做单目标试验。

自动验证按风险安排：数据迁移/隔离/取消/恢复/打包依赖必测；界面重排以交互验收为主。新 schema 每次覆盖旧版本样本，不把“最新版本新建项目通过”当作迁移通过。

性能先设可测目标再优化，例如 1 万张卡片、1 万条素材、300 个镜头的固定样本；记录测试机器与冷/热缓存，测检索延迟、列表首屏、保存延迟、导入内存和退出等待。以上规模是拟定验收数据集，不是当前产品已达到的性能指标。

## 11. 实施时需守住的技术边界

- SQLite 单库事务能保护本库状态；多个独立连接、数据库和磁盘文件不构成天然原子事务。即使用 ATTACH，跨库崩溃原子性也受主库与 journal mode 条件影响，因此本方案采用任务阶段、不可变原件、项目事务和可重建索引。[SQLite ATTACH 说明](https://www.sqlite.org/lang_attach.html)
- 明确校验每个 SQLite 连接的外键状态；不要仅凭 SQL 里写了 REFERENCES 就认为所有运行环境都执行约束。[SQLite 外键文档](https://www.sqlite.org/foreignkeys.html)
- 媒体继续通过受控自定义协议给界面；协议权限、session 和处理函数由主进程管理。库/项目 ID 只能解析到已经登记且位于合法根目录下的文件，切库/关项目时撤销对应映射。[Electron protocol 文档](https://www.electronjs.org/docs/latest/api/protocol)
- 本机 Node.js v24.19.0 已探测到 backup 函数和 FTS5 trigram；这是开发环境能力探测，不等同于 Electron 内置 Node、SQLite 和最终 ZIP 已验证。正式引入时必须在目标运行时补验。
- 以上任务属于后续开发计划。当前真实用户数据继续保留在仓库外的 WaterCut Projects，文档编写不对其执行升级、复制或删除。
