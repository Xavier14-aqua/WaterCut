## 数据约定

- 应用 v1.2.0、项目格式 v8、全局库格式 v1 分别管理。
- 旧项目升级前用 SQLite `VACUUM INTO` 生成 `project.sqlite.before-v8.bak`，升级事务失败回滚。
- `assets.storage_kind` 区分项目本地副本和全局引用；引用保存库 ID、源素材 ID 和哈希，不把用户总库绝对路径写入项目。
- 项目卡片保存来源版本和内容快照；布局与项目备注独立。普通关联和镜头顺序连线分开识别，分叉 / 环路必须确认排序。
- `script_blocks.shot_id` 唯一关联镜头，转换后的正文从镜头读取；脚本、分镜和时间轴共同修改同一镜头序列。
- 项目修订号与 outbox 由 SQLite 触发器维护；使用索引可重建，库不可用时不回滚已完成的项目正文保存。
- 原件引用不等于完整项目备份；跨电脑需同时携带引用的总库。当前全局删除采用隐藏，不自动清理原件。

## 自动化验证

命令：`npm run typecheck`、`npm test`、`npm run make`、`npm run smoke -- --packaged`。

本地验收：类型检查通过，40 项数据 / 路径 / AI 测试通过；v1.2.0 ZIP 构建与 19 项包内界面检查通过。包内入口、preload、worker 和 renderer 已核对，ZIP 与 app.asar 未发现个人项目数据库或本机配置；校验值保存在分发目录的 SHA256SUMS.txt。

数据测试覆盖旧版本迁移、较新格式拒写、引用隔离、隐藏与原件保护、取消与续传、标签 / 短中文查询、来源更新、脚本转换 / 拆分 / 合并、排序与时长、使用索引、目录设置、AI 请求字段最小化。测试用临时数据库和自制媒体，不使用真实项目。

界面脚本在隐藏的 Electron 窗口中加载生产界面，使用临时 userData、项目目录和全局库。检查示例、白板连线、脚本编辑、待拍状态、混播暂停、拖边、总库建卡、卡片孵化、真实 VP9 视频入 / 出点、seek 与换序；验证后删除对应临时数据。`--packaged` 进一步验证入口、preload、worker 和 renderer 均可从 `app.asar` 运行。报告及截图位于忽略的 `out/review-stage12/`。

这些自动检查不替代陌生用户电脑上的实际验收；系统编解码支持、未签名启动提示和真实 AI 服务仍需对应环境验证。

## 手动验收步骤

1. 完整解压 ZIP 并启动；在“存储”选择仓库外的项目目录和全局库目录，重启确认保存。
2. 在总库创建情绪卡、场景记录，给卡片添加图片 / 音频，检查主色条、时间、标签和检索；建立带备注的手动关系。
3. 选择卡片孵化 A 项目，再在 B 项目引用同样原件；修改 A 的卡片和裁剪，确认 B 与总库内容不变。
4. 更新总库原卡，在项目检查器比较并确认应用更新；位置与镜头来源仍保留。
5. 隐藏总库素材，项目预览仍可用；移除项目引用不删除总库文件。移走受管原件后重新定位，错误内容应被拒绝。
6. 用旧 v7 项目的测试副本打开，确认备份、镜头、原件、卡片、裁剪和白板均保留；加入总库时取消一次，再继续，检查没有重复卡片。
7. 白板框选有环 / 分叉的一组卡片，确认顺序后转镜头；删除一张来源卡，镜头保留来源摘录。
8. 文档中写正文并转镜头，在双栏与分镜互改对白；拆分 / 合并须经过确认，检查素材候选和来源规则。
9. 图片、视频、无素材镜头混排；预览暂停不推进，视频按入出点播放；时间轴换序和拖边后重开仍一致。
10. 标记待拍与待优化，修改景别 / 运镜 / 场景，查看清单分组并导出 CSV。
11. 无 Key 完成上述离线路径；使用自己的 Key 时，草案确认前不写分镜；失败不会覆盖原稿。
